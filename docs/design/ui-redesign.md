# 子智能体模型 UI 重设计（提案，待确认后再改代码）

> 目标：一个插件、三个位置，**不拥挤**；子会话里只做"切我自己的模型"；点按钮不再往对话里写命令条目。

## 1. 现状问题（来自你的四条反馈 + 我复核的两条）

| # | 问题 | 证据 | 根因 |
| --- | --- | --- | --- |
| 1 | 点一下面板，对话里出现一条命令调用 | 截图里成串的 `subagent-models · {"source":…}` | 面板**读**允许列表也走 `commands/execute`，而 commands 通道会写 `command/run` + `command/done` 到会话日志；每次打开面板都读一次 → 每次都留痕 |
| 2 | 面板太挤、布局不合理 | 截图 1/3/4：标题、状态、列表、部署默认、添加行、子智能体、切换、三行说明、状态栏全塞在一个 380px 面板里 | 一个面板承担了两种角色（配置 + 监控 + 操作），没有分区与层级 |
| 3 | 子智能体界面里还显示允许列表/兄弟列表 | 截图 3/4 | 面板不区分"当前会话是主会话还是子会话" |
| 4 | 布局杂乱 | 行内文字溢出到下一行标题、长 model id 挤压 | 没有截断策略，缺列对齐 |
| 5 | 每次操作后状态行堆积 `✓ Session allowlist saved: …` | 截图 1 | 成功也写状态行；失败（`session/agent-busy`）同样堆着不消失 |
| 6 | 打开面板就会命中 `session/agent-busy` / `writer-held` | 截图 2/3 | 面板在别的会话正写日志时发命令 → 直接报错（而且错误留在对话里） |

## 2. "点击出现工具调用"该不该有

**不该。** UI 的动作不应该变成对话里的命令记录。分两类处理：

- **读**（允许列表、当前路由、子智能体清单）：改成**零 RPC**。允许列表可以注册一个 Host 侧会话投影（`ctx.get("sessionProjections").register({ key: "subagentModelPolicy", … })`，官方 `modelSelection` 就是这么做的），客户端从 `projectionsBySession[id].values.subagentModelPolicy` 直接读；路由与子智能体清单本来就已经能从 `modelSelection` / `subagentCatalog` 读。**打开面板不再产生任何会话事件。**
- **写**（改允许列表、切模型）：走 `commands/execute` 是当前唯一"经过校验"的写通道，它**必然**留一条 `command/run`。两条路：
  - **A（保守，建议先做）**：只在用户点「添加/移除/切换」时写一次，一次一条；成功不显示状态、失败才显示一行红色。噪声从"每次打开面板 N 条"降到"每次真正修改 1 条"。
  - **B（彻底无痕，需先做可行性验证）**：自建 typert Remote（Host `ctx.typert.register` + 客户端 `ctx.remote.$mount`）。客户端装配是源码常量，第三方能否挂自己的 namespace 需要实测；风险是跟着 typert 契约走，跨版本更脆。**建议本轮先 A，B 作为可选 spike。**

另外 `session/agent-busy` / `writer-held`：这是"目标会话正在被写"的互斥，不是我们的 bug。设计上做两件事：面板打开时**不再发命令**（问题 1 修好后自然减少），写失败时就地显示一行"该会话正忙，稍后重试"，且**不写进对话**（这是面板内文本，不是会话事件）。如果 A 方案下命令行的 `kind: error` 也进日志，那就在面板里先做前置判断（读投影里的 writer 状态）再决定是否允许点。

## 3. 能展示哪些信息（数据可得性）

| 信息 | 来源 | 可得 |
| --- | --- | --- |
| 当前会话实际路由（model + effort） | `modelSelection` 投影 | ✅ |
| 是否继承 / 待生效切换 | `next != lastUsed` + `subagent` 描述符 | ✅ |
| 子智能体列表（label / mode / 层级 / 是否运行） | `subagentCatalog` + `byId[id].running` | ✅ |
| 每个子智能体的实际路由 | 同上（自己的投影，或沿 `parentId` 找祖先） | ✅ |
| 按模型分组的计数（"5 × deepseek-flash / 2 × gpt-6.1-sol"） | 遍历子树聚合 | ✅ |
| 允许列表（本会话 / 部署默认） | 新增投影 + `subagentModelSelection` 服务 | ✅ 新增后 |
| 逐轮路由历史（它换了哪些次、每轮用的什么） | 无投影 | ❌ 客户端拿不到 `request/header` |

**参考 dsh-subagents-model 的做法**：它那块 popover 的优点是"一行结论 + 一条细进度条 + 分组行（模型 / effort / 数量）"，没有任何说明文字；缺点是信息密度对单会话不够。我们取它的"结论先行、分组行、无长句"，再补上"可操作"。

## 6. 评审后修订（v2，2026-10-31 第二轮）

### 6.1 误操作：把"选中 → 底部切换"改成"行内 ⇄"

v1 的两段式（先点行、再到底部确认）有两个问题：选中态和操作框隔着整个列表，**看不出一一对应**；行高亮也容易被当成"当前正在看"而不是"将被修改"。v2 改为：

- 每行右侧一个 @BT@⇄@BT@ 按钮，点它**只展开这一行**的切换条（就地在行下方），确认按钮就是这一行的；
- 展开的行的背景轻微高亮，切换条与行首缩进对齐，视觉上父子关系明确；
- 底部不再有"选中 → 切换"，主会话面板里**不能**切换主会话自己（那是顶部模型选择器的职责）；
- 高风险动作（目标行下面还有继承它路由的子智能体）在切换条下加一行提示："它下面有 N 个子智能体继承该路由，会一起变"。

### 6.2 右上角"继承默认"确实含混：拆成三个模式

原来那个 badge 把两件事挤成一个词。现在分两个维度，各自显式：

**维度 A：允许集合（谁可以被派出去）** —— 三段式选择器

| 模式 | 含义 | 门禁 |
| --- | --- | --- |
| 本会话白名单 | 用本会话保存的路由列表 | 硬门禁：列表外拒绝 |
| 跟随部署默认 | 用部署 @BT@subagent-model-selection-settings@BT@ 的列表 | 硬门禁：列表外拒绝 |
| 不限制 | 没有任何列表 | 门禁关闭，纯继承 |

**维度 B：单个子智能体的路由来源** —— 行内 badge

| badge | 含义 |
| --- | --- |
| （无） | 自己显式选过，@BT@next == lastUsed@BT@ |
| 继承 | 自己没有路由，跑的是父会话的路由 |
| 待生效 → | 已排队新路由，下一轮起生效 |
| 启动路由 | 描述符里记了启动时的路由，但还没发过请求 |
| 未知 | 整条父链都没有记录（不猜） |

你提到的"默认继承主会话"属于**维度 B 的默认值**（子会话没有显式路由时跑父会话的），不是维度 A 的第三项。v2 用"不限制"表示维度 A 的第三项，正是为了让这两个概念不再混在一起。

### 6.3 状态覆盖 review（含 v1 漏掉的）

| 状态 | 触发 | 显示 | 可否操作 |
| --- | --- | --- | --- |
| 自有路由 | 显式 spawn / 切换后跑过一轮 | 只显示模型 | ⇄ 可切 |
| 待生效 | 切换到下一轮之前（@BT@next != lastUsed@BT@） | 琥珀 badge @BT@待生效 →@BT@ + tooltip 写"上一轮 x" | 可再切（覆盖排队） |
| 继承 | 子会话没有 own route | 灰 badge @BT@继承@BT@，模型名后加 @BT@(继承)@BT@ | 可切（切了就变成自有） |
| 未知 | 父链都没有记录（父会话已关闭等） | @BT@未知@BT@，不显示猜的模型 | 可切 |
| 启动路由（**v1 漏**） | 描述符有 @BT@agentModel@BT@，但投影里没有 @BT@modelSelection@BT@ | @BT@启动路由@BT@ + 模型名 | 可切 |
| 运行中 / 空闲 | @BT@byId[id].running@BT@ | 绿点 / 灰点 + 列表头"N 运行中" | — |
| 深层只读（**v1 漏**） | 目标不是直接子会话（d≥2） | badge @BT@d2 · 只读@BT@，⇄ 置灰 | 否（见 6.4） |
| 当前路由不在白名单（**v1 漏**） | 白名单被改小，已有子会话仍在跑旧的 | 行尾琥珀 ⚠ + tooltip "当前路由不在白名单；本次能跑完，下次派发会被拒" | 可切到白名单内 |
| 切换被拒 | 目标路由不在允许集合 / 会话正忙 | 面板内一行红字，不进对话 | 重试 |
| 冷态（进程内无 Agent） | 子会话已释放 | 仍显示投影里的模型 + 待生效（若能读到） | 可切（走 resume 覆盖） |

### 6.4 一个必须在动手前定下的规则

主会话面板列的是**整棵子树**（d1、d2…），但宿主侧 @BT@/subagent-model-switch@BT@ 现在只允许**直接父会话**改自己的孩子（安全规则：只有 parent 能改）。两条路：

- **保守**：d≥2 只读，提示"进它自己的会话或它的父会话里改"（v2 图里就是这个状态）；
- **放开**：允许"父链上的任意祖先"改它的后代（仍然受允许集合约束），面板里所有行都可切。

我建议**先保守**，因为 d2 的允许集合来自它自己的父链，跨层改容易让人误判"为什么这条能切、那条不能"。你要放开的话我改一行判据。

## 7. 实现落地（v3，2026-10-31 第三轮）

### 7.1 术语先说清楚

- **父会话（parent session）**：谁派生出这个子会话，谁就是它的父会话。DSH 里记录在 @BT@header.parentSession@BT@ / 列表行的 @BT@parentId@BT@。
- **父链（parent chain）**：父会话 → 它自己的父会话 → … 一直到顶层主会话。子会话没有自己的路由时会跑父会话的；父会话也没有就继续往上找。
- **"d2 · 只读"里的 d2**：第 2 层（主会话的子会话生出来的子会话）。这纯属内部结构，已从界面移除。

### 7.2 界面上不再出现的东西

| 原来 | 现在 |
| --- | --- |
| @BT@d2 · 只读@BT@ badge、@BT@继承@BT@ 等内部标签堆在名字后面 | 只保留用户能理解的 @BT@待生效 →@BT@ / @BT@继承@BT@ / @BT@启动路由@BT@ / @BT@未知@BT@，其余进 tooltip |
| 深层子会话被列成不可点的行 | **只列直接子智能体**；更深的一律以"另有 N 个深层"计数出现，不给死行 |
| 层级号、session id | 仅 @BT@?dev=1@BT@ 或 @BT@localStorage['dsh.debug']='1'@BT@ 时显示 |

### 7.3 三个"模式"其实只有两个可切

实现时确认了官方约束：@BT@subagent/model-selection-policy@BT@ 是**追加型事件**，官方投影 @BT@subagentModelSelectionPolicy@BT@ 的 @BT@stateSchema@BT@ 是 @BT@array(...).min(1).nullable()@BT@，且 @BT@apply@BT@ 对空数组**直接 throw**（@BT@dsh-tool-subagent/lib/index.js:262-273@BT@）。所以：

- 能进入三个**状态**：本会话白名单 / 跟随部署默认 / 不限制；
- 但只能从"不限制" → "白名单或部署"，**写过的列表无法撤回**（撤回需要写空列表，那会让官方投影抛错）。

因此 v3 **不做**三段式选择器（那会假装可逆），改为一行状态 + 两个动作：

   允许集合  本会话白名单 · 2 条            [编辑列表]
   （编辑态）… 路由行 + 添加 + 导入部署默认 …

关闭门禁的唯一干净做法：清空部署设置并**新开一个会话**（新会话没有策略事件）。

### 7.4 读缓存，去掉对话里的命令噪声

- 允许集合**每个会话每次页面加载只读一次**（客户端内存缓存），打开/收起面板不再发命令；写操作后失效重读。
- 仍会留痕的只有**真正的写**：添加/移除/导入/切换各一条 @BT@command/run@BT@。彻底无痕需要自建 typert Remote（客户端 @BT@ctx.remote.$mount@BT@ + Host @BT@ctx.typert.register@BT@），是独立 spike，尚未做。
- 订阅式读取（注册我们自己的会话投影）这条路**放弃了**：@BT@sessionProjections.register@BT@ 要求 @BT@wire.viewSchema@BT@ 是真 zod schema（@BT@snapshot@BT@ 会 @BT@parse@BT@），本插件零依赖拿不到 zod，硬塞假 schema 会在客户端取投影时炸——不值得。

### 7.5 与 v2 草图的差异

- 行内 ⇄ 保留；展开条里加了"它下面还有 N 个继承这条路由的子智能体，会一起变"。
- 模式从三段式选择器降级为"状态行 + 编辑按钮"（原因见 7.3）。
- 主会话面板不再有"把当前会话切到"——主会话自己用顶部模型选择器。

## 8. 第四轮反馈（2026-10-31）

### 8.1 子智能体不能再开子智能体

装配层就掐掉，不靠提示词：

| 作用域 | 拿到的工具 |
| --- | --- |
| Team Lead / 无 Team 的 root 会话 | @BT@switch_agent_model@BT@、@BT@spawn_teammate_with_model@BT@（或 @BT@spawn_subagent_with_model@BT@）、@BT@configure_subagent_models@BT@、@BT@list_agent_models@BT@ |
| teammate | 只有 @BT@switch_agent_model@BT@（切自己）+ @BT@list_agent_models@BT@ |
| 无 Team 时的 subagent 子会话 | 无 |

另外 teammate 的 system prompt 段落改成"你可以用 switch_agent_model 改自己的路由，不要继续委派"，不再出现 @BT@spawn_teammate_with_model@BT@ 的说明（那段只给 Lead）。
测试断言：teammate 的工具集里没有 spawn/configure，且其 prompt 段落含 "must not delegate further"。

### 8.2 部署默认：一次性快照，但导入后可继续改

@BT@导入部署默认@BT@ 写入的是**本会话白名单**（一次性快照）。导入成功后面板**保持在编辑态**，可以直接增删——快照只是起点，不是只读。要让列表跟着部署变化，只能再导入一次（官方事件是追加型，没法表达"实时跟随"）。

### 8.3 i18n：跟随 harness 语言

- 字典：@BT@zh@BT@ / @BT@en@BT@，键完全一致（测试断言），扁平字符串（locale 服务只做扁查找）。
- 注册：@BT@ctx.get('locale').register('dsh-subagent-model-router', lang, dict)@BT@；重复注册会抛，按 HMR 场景 try/catch 保留旧字典。
- 取翻译：@BT@ctx.get('locale').bind(ns)@BT@；取不到时按 @BT@navigator.language@BT@ 回退，再取不到用中文。
- 客户端 @BT@inject@BT@ 增加 @BT@locale@BT@（这是 fluent 依赖：宿主没有该服务时面板不挂载；0.2.1-rc.5 有，参考插件也这么声明）。
- 覆盖范围：面板、chip、hover、tooltip、错误行全部走字典；Host 侧的工具描述与命令文案保持英文（面向模型）。
